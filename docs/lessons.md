# Lessons

What this project's past changes taught us. Read all of this before changing an API, a format or an
agreed behaviour here. For the full story of a line, find the entry with the same date and name in
`lessons-full.md`.

When one has to change, add the full entry to `lessons-full.md` and one line here, newest last, in the
same commit as the change. Never merge lines to save space; before this file passes 80 KB (what one Claude Code read returns, measured 2026-11-15), ask the user.

- **2026-10-27 firewatcher: the model's excerpt is built from where the events are, not from the file's ends**: when a record must be cut to a budget, record where its important parts are while writing it, cut around those, and keep the end where outcomes show. A budget split must never shrink a piece when the budget grows (a superseded attempt that did kept producing new edge cases).
- **2026-10-27 firewatcher: --requires-mounts-for paths are normalized as text, never resolved on disk**: when you write a value into another program's file format, test what that program reads back for each odd input, against the real program. Transform the value only as the reading program would (here as text, like systemd), never by consulting state that may be absent or hung at the time you write.
- **2026-11-03 firewatcher 1.65: the verdict moved to the receiver**: when a pipeline gains a smarter stage downstream, move the judgment there whole, and keep only the rule-based floor (`always_notify`) at the source.
- **2026-11-03 firewatcher 1.65: a URL is parsed once, by our own strict rule**: when a value is both used for requests and written to logs, parse it once with our own strict rule that behaves the same on every runtime, not a lenient library parser. Record what that refuses that used to be accepted, as the entry above does.
- **2026-11-14 firewatcher 1.68: --install-service checks and renders everything before it writes**: an install that writes several files checks and renders all of them, by the rules of the program that will read each one, before writing any, so a refusal leaves nothing behind; a step that fails after the writes (a systemctl call) still leaves them, and a half-done install is state that changes what the next install does.
- **2026-11-23 firewatcher 1.69: the service reads UTF-8 paths in any locale, so the install no longer refuses a non-ASCII one**: when a value is refused only because a later reader cannot handle it, fix the reader and drop the refusal: the refusal closes one way in and leaves every other way the value reaches that reader failing. A value that is not UTF-8 is still refused.
- **2026-11-23 firewatcher 1.69: the replay finds the saved line in the journal as it is now**: a position counted within a log that another program trims is checked against the log as it is now before it is trusted; when it cannot be found, read again rather than skip.
- **2026-11-23 firewatcher 1.69: the saved second ends at a distance from it, not at the first line of another second**: a reader that stops on a timestamp it reads from the lines must know which time the program that orders the lines uses; stop on a distance from it on the later side only (a stall stores lines shown far earlier among the ones you want), and test against a source that keeps the two apart and against the real journal's stalls. Apply it to every reader of the same lines (1.70 removed the replay that still stopped at the first later line).
- **2026-11-23 firewatcher 1.69: a failed install undoes what it did, in the order the tools need**: an install that can fail part-way records what each step changes before it runs it (the old text, whether the unit was enabled), and undoes only that, in the order the program that reads the files needs.
- **2026-11-24 firewatcher 1.70: the journal position is the entry's cursor, not what its line shows**: to resume reading a source, save the name the source itself gives each record (a cursor, an offset, a sequence number) and check it against the source before trusting it; never rebuild a position from the text the record renders as. When the name is gone, fall back by time and read again rather than skip.
- **2026-11-25 firewatcher 1.71: the read that is matched decides where a restart starts**: decide where to resume in the read whose records are then used, by the name the source gives them; an empty answer means "gone" only with a success status, and a failure before the first record keeps the position. The restart's reads have no bound, against LESSONS.md's bound-every-wait line: a late answer is still an answer, a stop ends the wait, and a first answer that is 30 s late gets a log line saying what is waited for (the reasons in lessons-full.md).
- **2026-11-25 firewatcher 1.72: a stop is a wake-up the loop reads, never an exception thrown into it**: in a program with threads, a stop signal's handler only notes the stop and wakes the main thread through a descriptor that every one of its waits selects on (`signal.set_wakeup_fd`), and the stop is acted on there, between two units of work. Never raise it wherever the main thread is (it lands inside locks and half-done work), never count on the main thread taking it (the kernel hands a process's signal to any thread), and never mask it in helper threads that start processes (the processes inherit the mask).
